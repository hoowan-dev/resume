I am writing to express my strong interest in the \textbf{Software Development Engineer II} position on the
Luna SIPS team. Over the past five years at Electronic Arts, as a Gameplay \& Animation Software Engineer at
\textbf{Maxis} on \emph{Project Rene} (\emph{The Sims}) and now as a Tools \& Tech-Art Software Engineer at
\textbf{EA Lifestyle}, I have designed performance-critical systems in C++ and built automation that removes
manual work for the people who depend on it. Having spent my career building games, I understand what a
player feels when a session is slow to start or stutters, and I would be excited to work on the
infrastructure that keeps Luna fast and reliable.

At \textbf{EA Maxis Studios}, I architected a multi-threaded, asynchronous path-planning and navigation API that
served deterministic routing queries for dense crowds within a frame budget of under 1.5ms. Getting there
meant designing for concurrency and predictable latency from the start, then profiling, benchmarking, and
optimizing compute and memory usage across a large, multi-disciplinary C++ codebase. I also built diagnostic
tools and visual debuggers that let designers, animators, and QA find and triage problems quickly, which
shaped how I think about observability: the faster a team can see what a system is doing, the faster it
can fix it.

At \textbf{EA Lifestyle}, I architected a Maya/Python automation tool adopted across multiple internal studios
that cut redundant manual work by over 70\%, and engineered a high-throughput Unreal Engine C++ plugin that
exports runtime data pipelines for motion-matching databases. Earlier, I led an intern team at
\textbf{TurnUp} building an Express.js API and React Native client, where I owned pull requests, code reviews,
and unit testing, and as a research assistant at \textbf{Boise State University} I developed a distributed
content production pipeline with image processing, compression, and database schema design. More recently, I
automated an end-to-end, agent-driven document pipeline with scripted builds and output verification.

My background is in game systems rather than cloud fleet management, and I am eager to apply the same
habits to SIPS's problems: designing for reliability and scale, measuring before optimizing, automating
away toil, and owning features from design through production. I bring experience with C++, C\#, Java, and
Python, object-oriented design, design and code reviews, and technical roadmap planning.

Based in Seattle, I would welcome the chance to help Luna provision and run game sessions efficiently at
scale. Thank you for your time and consideration. I look forward to speaking with you.
